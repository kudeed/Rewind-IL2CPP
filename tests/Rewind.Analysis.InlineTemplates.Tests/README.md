# Core async recovery chain regressions

This package-free executable tests the existing Analysis/Core binaries. Build the complete recovery branch first, then build and run the tests once as a batch. `RewindBinaryDir` can point to the newly built Lab or CLI directory.

The native evidence comes from PAP's ARM64 IL2CPP binary, not substitute SDK code:

- Generic `UniTask<SceneInstance>.GetAwaiter`, RVA `0x5F911A0`, clears its return buffer before copying its complete `task` field. The caller inlines the copy without that redundant clear. Template construction must verify the exact closed generic layout and every instance field before omitting the clear from its comparison. A receiver call is evaluated exactly once, in its original position.
  Candidate discovery also follows a nested wrapper to its containing type with the exact leading generic arguments. This lets the ordinary member search find the public method that produced the wrapper, rather than only methods declared on the wrapper itself.
  The hidden return buffer is marked `AddressTaken`. Computing the address of a value-type local's field for a store does not read its former contents; that flag must not move a receiver factory behind a fictitious read. Class, byref, pointer and array destinations retain the conservative order check.
- `UniTask<SceneInstance>.Awaiter.GetResult`, RVA `0x63CACBC`, calls the real source with the original token on the non-null branch and returns both `x0` and `x1`. Its cached branch uses `ldp x0,x1,[x8,8]`. An unknown indirect call must therefore preserve both possible result projections until the actual managed signature selects the valid ones. Known scalar, void and floating results still invalidate `x1`.
- `CoreScenesHandler/<LoadAndActivateScene>d__13::MoveNext`, RVA `0x419F1B0`, intentionally ignores that first result. A separate effect-only comparison template removes only nonthrowing result-local work. It retains source calls, getters, class dereferences, checked arithmetic, exceptional exits and external writes; it never changes the ordinary result template or shared recovered body.
- The same caller first uses `[sp]` for a 32-byte generic task, then stores the two-word nongeneric task there at `0x419F464`. A complete pair from one STP and a verified return layout proves the new stored type. Incompatible prior types request the existing per-byte reaching-definition stack-lifetime split. Exact nested struct-field views remain valid. Unknown layouts, partial pairs, modified words and overlapping fields do not provide this proof.
  The proof also enables the splitter's existing strict filtering of captured stack arguments the actual ABI never takes, already used for incompatible struct arguments. The native trace showed those speculative reads joining both lifetimes. A load with any real consumer still participates in reaching definitions. Normalized partial copies and modified return words remain unproved. Optional `REWIND_RETURN_STORAGE_TRACE` takes a method-name substring for inspecting this boundary.

`Program.cs` exercises the actual `Make`/`TryFold` wrapper boundary, nested candidate search and address-taken return-buffer ordering, with strict rejection cases. `IgnoredResults.cs` exercises `MakeDiscardedFlow`/`TryFoldFlow`, interpreting both original and rewritten HIR to compare source identity, nonzero tokens, call counts, null handling and exception-before-continuation order. It also refuses used returns, mismatched tokens, divergent continuations, missing getter effects, division failures, null dereferences and address-visible return storage. `Arm64Results.cs` tests the actual return-register capture and result-storage recognizer, then runs the existing `StackSplitting` pass on straight and branching control flow to verify both new words still read their own stores after separation, including real versus untaken call arguments at a join.

The two primary native end-to-end samples are `GameEndPodium/<LoadSkin>d__23::MoveNext` and `Paper2.GameFlow.Scenes.CoreScenesHandler/<LoadAndActivateScene>d__13::MoveNext`. The pre-change evidence is under `/data/home/game/pap_autonomous/20261128-v8-batch/resume-20261128-0212/value-snapshot-patch/whole-value-r1/` and `public-api-probe-r1/`. Final emitted C# compilation uses the actual Unity reference profile and explicit validation-only metadata for other game types. No generated metadata assembly is a runnable SDK implementation.

No match depends on the names `UniTask`, `GetResult` or `SceneInstance`; each is established from recovered code, exact type/layout information and matching effects. SDK visibility and real runtime libraries are unchanged.

## Complete scalar structs in wide stores

PAP `Player::ResetTrailCollider` (token `0600059E`, RVA `0x3B29F88`) loads the complete eight-byte static `DummyColliderPoint` at `0x3B2A1D8`/`0x3B2A1E8`. Each `str d0` writes the first two fields of a `Vector3`; separate `str wzr` instructions set the third field to zero. `Player::EndBotLease` (token `06000521`, RVA `0x3B2F348`) has the same pattern at `0x3B2F73C`/`0x3B2F750`. Before this correction the HIR treated that typed `Vector2` as an integer and emitted `conv.i4(value)` and `value >>> 32`. This defect occurs in recovery before C# decompilation.

`StructStores.cs` exercises the actual store/decomposition boundary with numerical values, signed zero, NaN payloads, infinities, a getter evaluated once, exception-before-write ordering, overlapping source/destination storage and closed nested generic layouts. The new path requires every byte of the complete small struct to belong to a known scalar field. It refuses partial words, unknown or overlapping layouts, padding and references. Field copying uses the recorded layout, without matching Unity or game names. Existing async, ARM64-result and stack-lifetime regressions run in the same executable.

Native capture uses the unchanged ELF SHA-256 `cf0fe59687988793400852978382bef8626a29326f53d2ccedb16b4db79a2bec`; before/after bounded HIR receipts are kept under `/data/home/game/pap_autonomous/20261128-v9-rewind-parts/`. These tests validate this recovery boundary, not complete game runtime behavior.

## Omitted closure receivers

PAP `CardOfferShopItem/<>c__DisplayClass48_0::<FlipToNewOffer>b__0` (token `06007AFC`, RVA `0x4096314`) loads its captured owner from `[x19 + 0x18]` into `x8` at `0x40963A0` and `0x40963E4`. Both loads immediately precede a null-throw guard and a direct instance getter call (`0x40949C8`, `0x4094A2C`). Each getter overwrites incoming `x0` on every path before reading it; its compiled body does not consume the instance argument. The compiler therefore left the caller's `x0` holding the closure or an earlier `AudioObject` result.

Previously, guard removal made these owner loads dead. HIR then used the stale ABI register for the two getters. The correction retains the adjacent checked object as a non-ABI call input so normal dead-code and SSA replacement passes preserve its original load. HIR selects it only when its managed reference type fits the declaring type, without inserting a cast.

The native proof deliberately accepts only a uniquely identified non-generic, non-virtual reference-type instance method whose raw lifting never reads the incoming receiver register. It refuses missing/incomplete bodies, methods that read `this`, shared identities, constructors, forwarded and indirect calls. The caller proof requires the correct null edge, one predecessor, the same exception scope and no intervening effect. `ClosureReceivers.cs` tests both ARM64 and Win64 register numbering, both null-test polarities, stale closures and call results, owner-load liveness after dead-code cleanup, subclass identity, type rejection and ambiguity. It compares the native caller's explicit null check with execution of the recovered managed call for null owners and throwing getters, including read counts and effect/continuation order.

The bounded before/after native evidence is under `/data/home/game/pap_autonomous/20261128-v9-rewind-closure/` on mj5, using the same ELF hash recorded above. This is a recovery-boundary regression, not a whole-game runtime claim.
